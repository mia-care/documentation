## November 2026 (v3.7.6 to v3.8.0)

## October 2026 (v3.7.0 to v3.7.5)

### P4SaMD v3.7.5, 30 October 2026 (patch)

A patch release that adds organization branding, two new Brownfield target frameworks, and a number of fixes, including a long-standing sign-in issue. It also updates the wording of many existing compliance checks to match the official regulation and guidance text more closely, which can change the outcome of a Brownfield gap analysis.

:::info Brownfield gap analysis: some results may change
This release rewrites many compliance checks across IEC 62304, ISO 14971, IEC 62366-1, NIS2, MDCG 2019-16, the MDR, the AI Act, GDPR, and the FDA cybersecurity framework to match the official regulation and guidance text more closely, and turns off a number of NIS2 and GDPR checks that were not adding reliable value. If you run a gap analysis again against one of these frameworks, you may see different findings than before. MDR gap analysis sessions now also evaluate against the MDCG 2019-16 guidance, which can surface findings that did not exist in an earlier run.
:::

:::note Document templates: not yet available
This release adds the ability to store and generate tenant-authored document templates, and a published template will appear in the Documentation Hub next to the built-in documents. You can ask your System Administrator to create a customized template for you and publish it on your behalf. There is no page in the product yet for creating a template, so this is not something you can use on your own in this release.
:::

## September 2026 (v3.5.1 to v3.6.0)

### P4SaMD v3.6.0, 17 September 2026

Version 3.6 adds a Reconciliation view that compares your System Design against the latest SBOM scan, component by component, and lets you resolve any mismatch directly from the platform. Unit test reports gain free-text tags and a two-step download (raw or traceability-enriched, as PDF, CSV, or JUnit XML). Git connection errors on a linked repository now explain what went wrong instead of showing a generic failure, and target market regions are limited to the platform's current assessed scope.

<FeatureGrid>

<FeatureBox icon="🔍" title="SBOM Reconciliation">

A new Reconciliation view under System Design compares each software item's declared SOUP (Software of Unknown Provenance) components against its latest SBOM scan, and lets a reviewer resolve every mismatch: accept the scanned value, fill in a missing one, mark it approved as designed, match or unlink an item, create a draft entry, remove it from the design, or ignore it with a justification. A badge on the Software Items list flags any item with reconciliation outstanding.

</FeatureBox>

<FeatureBox icon="📄" title="Report Tagging and Two-Format Downloads">

Unit test reports can now carry your own free-text tags, and the report list and test case list can be filtered by them. Downloading a report is now a two-step choice: Raw (the file as uploaded) or Traced (enriched with traceability information), each available as PDF, CSV, or JUnit XML.

</FeatureBox>

</FeatureGrid>

P4SaMD v3 is a new platform. There is no direct in-place migration path from v2. To move from v2, we recommend using the **Brownfield Import** feature to onboard your existing projects into the v3 platform. Contact Mia-Care for migration support.
